## 一、下一版本：独立聊天模块 <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| 功能 | 状态 | 确认来源 |
| --- | --- | --- |
| 用户与师傅聊天 [**IM**](https://en.wikipedia.org/wiki/Instant_messaging) | 已预留模块边界，下一版本实现 | 2026-10-05 用户要求 |
| 消息类型、离线消息、送达／已读、附件、推送、客服介入 | 设计前逐项确认，不视为首期已交付 | 聊天模块的后续设计项 |

模块约定见 [`Server/internal/im/README.md`](../后端/Go服务端/internal/im/README.md)。订单、审核和账务服务不能直接处理聊天连接、消息存储或推送。

- 聊天拥有自己的会话、消息、附件及实时连接实现，通过独立接口对外提供能力。
- 登录账号通过适配接口传入聊天模块；模块不依赖订单服务的具体类型。
- 订单关联使用不透明业务引用，例如 `businessType=repair_order` 与订单 ID；由应用层连接两个模块，不把订单状态机搬进聊天模块。
- 各端聊天 UI 与数据访问独立组织；后续可替换自建或第三方聊天服务，无须修改订单、审核或账务的核心逻辑。
- 本期不启动聊天服务、不创建聊天数据表、不增加聊天网络请求。

## 二、支付和数据库的后续阶段 <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| [**支付宝**](https://open.alipay.com/) | 接口预留，未接入 | 商户资质、应用与服务端密钥 |
