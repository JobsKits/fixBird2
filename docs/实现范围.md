## 一、<span id="business-scope">业务实现范围</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| 模块 | 工作台合同与目标 |
| --- | --- |
| 账号与权限 | 合成角色登录、企业及当前经办人过滤、职责字段矩阵、同企业交接／撤权、停用启用与旧会话失效 |
| 工单 | 寄修、上门、销售；工单主线持续至整单完结，保留履约结果与事件时间轴 |
| 报价与签署 | 报价版本、公司审核、客户同单确认、明确先款约定；人工验收通过／不通过均追加原件历史 |
| 履约 | 收件、分派、检测报告、维修、质检、销售备货、人工物流、交付验收 |
| 资料票款 | 资料与开票要求明确、文件与发票记录、现金收退、人工核实与内部交接、待收展示 |
| 完结 | 核对资料、票据、款项、借还、争议及余项；人工完结、重开、返修关联 |
| 库存采购 | 采购收货、可用与隔离库存、借还、耗用、处置与转交记录 |

| 安全审计 | HTTP 登录／失败／退出、鉴权拒绝、详情／原件下载／导出、账号状态变更及恢复留痕；管理员分页查看 |
| 网页与离线 | 响应式页面、服务端工单分页、首屏样例、嵌套响应校验、当前 401 撤销清旧资料、独立演示回退与自动恢复、动态列表空态与重载 |

模块接口见 [工作台接口合同](./workbench-contract.md)。上述表为核对范围；具体实现与已测能力以本页 [验证记录](#verified) 为准，不能将接口清单直接视为全部端侧完成。

当前 TiDB 保存单个加密聚合快照并以 revision 防止旧进程覆盖，定位为小规模业务框架。尚未按 PRD 将全部业务拆为规范化关系表，也未建立复杂多设备、多批次的明细履约、分批签署及独立金额分摊模型。这些能力需继续设计、实现与专项验收，不能由“可录入多个文字记录”替代。

当前工单办理统一针对完整的有效履约范围。型号、数量等销售条款保留在冻结的报价描述中，尚未做结构化逐项出库一致校验；收件、派单与物流以人工事实事件记录。企业当前经办人可按权限办理交接，旧授权撤销并保留原签署快照；该能力不等于真实企业身份已经核实。

用户已明确维修仅在 `quote.startRequiresPrepayment=true` 时先款开修：正数约定预付款的已核实净额达到约定后才允许开修，未约定及旧数据缺省 false 不因预付款金额本身拦截。现款销售仍要求核实净收款达到冻结报价总额后出库，账期销售保留预付款条件，详见 [执行门槛合同](./workbench-contract.md#execution-payment-contract)。

人工验收通过或不通过均追加签署原件、签署人、时间、报价及工单版本；不通过关联异议，后续通过不覆盖先前原件。完整历史限当前授权客户经办人及管理员／调度／财务，摘要和其他角色不含原件；普通页面只读展示，公开 API 的不通过提交有正式测试。新质保按中国日历月取目标月同日或月末，并覆盖截止日全天。已有截止日不自动重算，旧版本丢失的原件不补造，见 [验收与日历合同](./workbench-contract.md#acceptance-history-contract)。

职责读取使用 [统一矩阵](./workbench-contract.md#field-permissions)：管理员／调度／财务保留成本与提成；工程师／仓库仅本人成本及本人待核实现金，QC 和外部角色无成本提成。财务事件正文、内部资料与证据也按职责过滤，公开及本人上传的维修资料保留。当前私有附件依据阶段和付款／发票引用隔离，阶段不能替代正式用途分类，正式敏感资料仍需明确用途与授权。

文件隔离恢复验证完整当前账号来源并保留当前账号与工单 `customerId/companyId/assigneeId/ownerId`、证据删除约束、最新已消费请求键与摘要和按稳定 ID 合并的审计；任一旧工单／旧证据缺少当前约束则拒绝，不恢复旧权限。恢复的报价、签署、款项及库存仍来自备份点。最新仅有账号状态键按当前授权重建，其它业务键返回 409 待核对、不重执行，跨后续恢复保持约束。最新源缺失仍拒绝，尚未提供主机全损情况下仅靠旧备份的完整恢复路线。

完整详情、完整工单幂等重试、原件下载和导出在返回资料前持久保存审计，保存失败即拒绝；账号变更原因、前后状态及授权版本与账号同事务保存。列表／bootstrap 在同一业务锁内重查当前账号，不批量记录每条摘要读取。审计目前仍在应用加密快照内，没有独立运维审计或不可篡改副本。

首屏默认 30 条 `isSummary=true` 工单与 `orderPage/metrics/capacity`；摘要不含完整事件、证据、报价历史、签名、成本、提成，详情及授权导出仍可读完整资料。工单搜索、筛选与翻页请求服务器，全范围概览不只统计当前页；库存／借还／采购仍以列表随首屏返回。写入仍克隆并保存整个聚合快照，独立媒体和关系表尚未实施。

幂等键及内容摘要全部保留，工单／借用／采购历史响应压缩为稳定资源 ID，启动兼容旧响应，重试按当前授权重建结果；不删关键键，不重复执行业务。累计 8,000 键预警，10,000 为参考阈值，已移除硬停写入。网页提交缓存前校验 2xx 嵌套字段，未知写入不报成功、不自动重放，原意图键不因无关弹窗丢失；明确成功后的另一笔同内容办理使用新键。当前会话任一受保护请求 401 都清旧资料并提示重新登录；非 401 故障完整回退独立演示，后续有效响应自动恢复。连接仅同源，`file://` 页面只作离线合成预览。

独立演示对未结异议、过期报价、未结提成、重开复核和返修继承边界提供阻断；借用按未归还且未转出数量计入完结缺项，归还最后一项后同步重算摘要和阶段。这些本地操作使用合成副本，不代表服务端已保存。

第五轮待修范围见 [后端问题](./五次回归报告-2026-10-15.md#backend)、[网页问题](./五次回归报告-2026-10-15.md#frontend) 与 [演示问题](./五次回归报告-2026-10-15.md#demo)：后端包括返修原单引用、免费零价报价、异议后的验收窗口恢复及交付时间一致性；网页包括动作／导出关联与嵌套完整性；演示包括借还审批及前置条件、完结后新增义务、退款／票据／资料、履约结果和预付款上限。已实现的部分保护不能覆盖这些尚未修复的边界。
