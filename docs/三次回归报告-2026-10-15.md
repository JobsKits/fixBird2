## 三、<span id="identity">R3-F01：换身份期间旧授权快照复用</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

管理员已加载工单与全范围指标，随后切换到客户。`login` 增加请求代次并清除详情缓存，却保留旧 `data` 与 server 数据来源；登录成功只先更新 `actor`。等待客户 bootstrap 时导航财务，`currentOrders` 对 server 快照直接返回旧 `data.orders`，页面已使用客户身份标签，记录和指标仍来自管理员。

| 阶段 | 登录身份／数据身份 | 展示结果 |
| --- | --- | --- |
| 客户登录成功，bootstrap 等待 | customer／admin | 旧快照仍缓存 |
| 导航财务，新分页等待 | customer／admin | 旧跨企业记录可见，旧概览标为“当前授权范围” |
| 客户分页先到 | customer／admin | 列表转为客户范围，旧指标仍保留 |
| 客户 bootstrap 后到 | customer／admin | 导航使列表序号变化；metadata 合并因旧 `data.actor` 不匹配而拒绝，旧概览仍保留 |

外部诊断使用可辨识合成指标：旧管理员 `remainingCents=99000000`，客户应为 `123`；全部响应结束后仍显示旧值，独立复跑两次一致。四阶段记录见 [诊断结果](./三次回归证据-2026-10-14/frontend-findings.json)。

真实页面使用同一浏览器，先登录管理员，再登录客户并导航现金与票据。代理只延迟实际响应，不改响应内容：bootstrap 约 4 秒、工单页约 2.5 秒，均低于本次页面设置的 15 秒超时。客户身份下显示了“青禾物业”记录；列表响应到达后该记录消失，但 bootstrap 也释放后，进行中指标仍为管理员的 **8** 单。独立客户 API 正确返回 **7** 单且没有青禾记录；手动重新加载后界面才回到 7 单。

这里确认的是前端旧授权缓存泄露／错误概览，未发现服务器为客户越权返回另一企业记录。真实种子的两种身份待收金额恰好同为 4,920 元，因此真实页面证明的是跨企业记录及 8／7 计数问题；不同金额的概览串用由外部诊断证明，不混用两套数据。

![客户身份切换期间显示缓存的青禾物业记录](./三次回归证据-2026-10-14/browser-identity-leak.png)

截图的滚动位置显示跨企业记录；同时刻 [界面文本](./三次回归证据-2026-10-14/browser-identity-leak.ax.txt) 与 [阶段状态](./三次回归证据-2026-10-14/browser-identity-results.json) 保存了客户身份标签。[代理时序](./三次回归证据-2026-10-14/browser-identity-timing.json)、[客户 API 正确范围](./三次回归证据-2026-10-14/browser-customer-api-expected.json)、[响应完成后的旧概览截图](./三次回归证据-2026-10-14/browser-identity-stale-metrics.png) 一并保留。

修复方向：登录切换时立即废弃旧身份的列表、概览、库存等授权快照；新数据到达前显示安全空态或独立合成数据。新 bootstrap 应验证本次登录身份及请求代次，不能因旧快照身份而阻止当前身份的元数据落地；列表和概览须归属同一当前身份。手动刷新只能帮助复核，不能代替隔离修复。

## 四、<span id="demo">R3-F02：本地演示缺省备注被清空</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

真实 `app.js` 在质检／仓库备注表单中只提供客户说明，生成的 payload 只有 `customerNote`。独立合成演示请求失败后由 `data.js` 的 `D.apply` 接续；它无条件执行 `o.remark = payload.remark`，把原内部备注置为 undefined，再更新客户说明。

诊断按真实 document click 打开详情、点击生成的备注按钮、提交实际表单运行，日志保留 `R3-F02_UI_PAYLOAD` 和更新前后值。不是单独调用不可从界面产生的 payload。修复时应与后端字段级更新保持一致：省略字段保留，有权限角色明确提交空值才清空；同时补演示与服务端行为对照。

此问题只损坏独立合成台账，不表示真实业务内部备注丢失。本轮真实质检页面保存客户说明后，管理员复核原内部备注仍存在，见 [真实页面正常场景](./三次回归证据-2026-10-14/browser-results.json)。

新增网页通过场景包括连续刷新与分页切换、较新 401 后旧 bootstrap 不复活资料、metadata 授权范围不匹配时拒绝并入、刷新队列换身份后旧结果不覆盖新状态、签名迟到不关闭新表单、关闭附件表单后的迟到读取不发原写请求、旧 close 事件不使新表单失效及未知签名响应不生成假成功。已发现的身份快照复用与演示备注问题仍须另修。

真实浏览器另验证配置保存期间导航仍取得配置 B、服务端质检客户说明更新保留内部备注、390×844 详情无页面横向溢出、搜索无数据空态及重新加载可用。搜索 0 条时全范围指标保持 8 单，见 [正常场景结果](./三次回归证据-2026-10-14/browser-results.json)、[移动空态](./三次回归证据-2026-10-14/browser-mobile-empty.png)。这不是实体手机或全部角色验收。

上轮 9 项修复、旧并发压力通过与本轮两个新问题分别记录；不覆盖历史证据，也不以现有测试全部通过宣称当前全部安全。聚合快照、独立审计、完整灾备、生产并发及完整 PRD 验收边界仍见 [实现范围](./实现范围.md)。
