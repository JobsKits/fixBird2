### 1.5、<span id="flows">业务流程与异常闭环</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| 流程 | 前置条件与主线 | 异常与终止 |
| --- | --- | --- |
| 寄修／上门维修 | 受理、检测、公司审核报价、客户同单签署、执行、质检、交付、验收、结算、完结 | 拒修、不能修、异议及退款／退件保留责任与余项；上门不套用寄修自动验收 |
| 配件销售 | 报价审核及签署、备货、出库、交付验收、资料票款、完结 | 现款按冻结报价核实净收款；结构化逐项出库校验尚需补齐 |

重复操作使用稳定请求键；版本冲突读取新版本后核对，未知写入保留表单与原键。读取失败、空数据和重新加载都有明确入口。服务恢复后采用后续成功响应；演示副本不自动上传正式台账。

### 1.6、<span id="personal-work-log">个人工作日志、日历与事件提醒</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

来源与范围：用户本轮明确增加每个账户的个人工作日志、日历历史、文字／图片／视频和待办事件提醒，随后确认本轮先完成 Web 与后端，App 后续实现。下表中的产品要求为 confirmed；其后的技术处理标为工程默认，不冒充用户逐项选定的实现。该日志独立于工单备注、工单附件和组织协作数据，不因同企业或参与同一工单而共享。

| 编号 | 已确认要求 | 页面与结果 |
| --- | --- | --- |
| WL01 | 每个账户拥有私密工作日志，普通账号不能读取或写入其他账号的日志及附件 | 归属由服务端会话确定；列表、月历、正文、媒体原件与提醒均隔离，猜测日期、账号或媒体 ID 不能越权 |
| WL02 | 管理员可以查看他人日志，默认不修改 | 本人日志正常编辑；查看他人时明确显示归属及只读状态，不能代写、替换附件、修改待办或取得他人提醒操作权限 |
| WL03 | 点击工作日志进入日历查看历史，默认打开今天的编辑备忘 | 可切换月份与日期，本人可编辑所选合法日期的日志，包括历史及未来预记；今日／有记录／当前选择可辨，历史空日、月历无记录与加载失败均有恢复入口 |
| WL04 | 日志支持文字、本地图片／视频和剪切板图片／视频 | 可选择本地媒体并在可读取的剪贴板文件粘贴时加入，保存前预览、移除；媒体不能经公开静态目录或无鉴权链接暴露 |
| WL05 | 待办可设置事件提醒 | 待办标题、计划提醒时间、当前状态可见，支持修改时间、完成与取消；完成或取消后不再触发原提醒 |
| WL06 | Web 提醒使用右下角 tips | 到时显示非抢焦点提示，可查看对应待办、关闭提示；不打断输入，不用模态弹窗或自动跳页代替 |
| WL07 | App 提醒使用顶部 tips | 保留为后续 App 实现要求；本轮不把 Web 右下角提示当作 App 已交付，也不把延后实现解释为取消需求 |
| WL08 | 账户切换、异常保存与重复进入仍满足隐私和提醒连续性 | 退出／过期／换号立即清理前一账户日志、编辑及媒体视图，旧请求和提醒不能回写新会话；失败不显示保存成功 |
| WL09 | 工作日志下提供“全部日志”列表及日志详情 | 跨月份读取当前所选账户的全部授权日志，提供分页或加载更多、空态与重新加载；点击条目进入对应日期的详情，不用当前月份或当前页数据冒充全部日志 |
| WL10 | 本人可以明确确认后删除自己的日志 | 管理员查看他人仍只读，不取得他人删除权；成功后同步月历、全部日志列表与当前编辑器，失败保留内容，旧版本冲突不误删 |
| WL11 | 提醒日期时间选择有明确确认与取消，时间字段与标题字段同高顶对齐 | 面板确认只回填当前表单，点击“保存提醒”才提交；取消／关闭不改变原值并恢复打开面板控件的键盘焦点，不丢失输入上下文 |
| WL12 | 今日新建日志显示完整日期、星期及 `HH:mm:ss`，历史不伪装当前时间 | 今日新草稿的编辑时刻与真实保存时间区分；已有记录按真实时间字段展示，历史空日只显示所选日期和星期，不用当前秒钟补造历史记录时间 |

| 当前身份 | 本人日志／媒体 | 他人日志／媒体 | 他人待办与提醒 |
| --- | --- | --- | --- |
| 未登录、会话过期或停用账户 | 不可读写 | 不可读写 | 不可读写及接收 |
| 普通有效账号 | 可读写，服从校验与版本 | 不可读取、下载、写入或获知月历摘要 | 不可读写及接收 |
| 管理员 | 可读写本人内容 | 可查看历史、正文及媒体，默认只读 | 不查询／修改／触发／接收他人独立待办提醒；日志中的文字不自动赋予提醒权限 |

工程默认与异常处理：

- 日志按账户与所选日历日期保存，今天根据客户端当前选择的本地时区计算。提醒由客户端选择当地日期时间并明确显示时区，后端保存 ISO UTC 时刻及必要的时区信息，比较使用统一时间基准；显示时区变化不悄悄移动已设时刻。跨午夜、月末及夏令时边界需验证，跨时区改时策略见 Q-005。
- 提醒为单次事件，不默认增加周期规则。以账户、事件 ID 及提醒版本识别同一次提醒，由后端原子认领／触发，防止多标签页、刷新、重开与轮询重复弹同一版本。修改时间形成新版本；关闭 tips 不自动完成待办，完成／取消须明确更新待办状态，触发时重新检查到期及当前状态。管理员查看他人日志不自动获得其提醒列表、触发或确认权限。
- 本轮以页面运行期间的站内提示为工程默认；页面后台节流后返回时补检本人未完成已到期事件，标明逾期并合并展示，不连续轰炸。已完成、已取消和已认领触发的旧版本不补弹。页面关闭、休眠、断网及服务停止时不承诺准点触达；系统通知、邮件／短信及后台推送未作为本轮已实现能力，见 Q-006。
- 日期切换、返回和关闭编辑器前，未保存内容须能继续编辑或明确放弃。API 失败保留当前账号的内存草稿，不把真实内容伪装保存到合成演示，也不写入浏览器持久缓存；身份切换清理草稿、预览及媒体 Blob。保存超时／响应不可解析按结果未知处理，保留稳定请求意图并先核对结果，不显示假成功或自动重放；版本冲突须重新加载核对，不能静默覆盖另一设备更新。
- 粘贴只处理用户主动粘贴时浏览器提供的可读内容，不后台读取剪贴板。无可读媒体、不支持格式、超限或上传失败时明确反馈，保留文字并提供本地文件选择，不把空媒体条目当上传成功。短视频采用可配置的工程限额；具体格式、大小、数量、保留期及浏览器兼容见 Q-007，演示通过不代表无限视频或全平台兼容。
- 文字按纯文本处理和转义，不执行日志中的 HTML／脚本；媒体元数据及原件每次访问重新鉴权，不信任仅由前端隐藏的入口、文件扩展名或 MIME。API 优先与合成演示分别隔离，未登录及故障回退不能暴露上一账户内容，真实日志、附件与提醒不复制到合成演示。
- “全部日志”使用独立于当前月历范围的授权查询，按当前所选账户分页或加载更多；条目可辨日期、摘要与实际保存状态，点击进入对应日志详情。更换账户、删除或重载后同步查询归属及列表状态，不能混入前一账户或遗漏跨月份记录；无记录和请求失败保留明确的恢复入口。
- 删除前明确展示本人目标日志日期及其媒体范围，用户确认后才提交当前版本；取消不改变正文、附件及选择。删除成功撤除该篇日志的可见正文、媒体元数据和原件访问，释放当前预览 Blob，并同步日历标记、全部日志列表和编辑器；不删除其他日期／账户的媒体，不连带删除独立事件提醒。失败、结果未知或版本冲突保留原内容并核对结果，旧请求不能重新暴露已删除的正文或媒体。已另存的媒体副本及既有备份不因界面删除自动撤销，相关恢复仍服从原有数据与授权合同。
- 提醒日期时间面板内的选择属于暂存状态，提供可辨认的“确认”和“取消”。确认后仅回填当前提醒草稿并关闭面板，只有“保存提醒”提交创建／更新请求；取消、Esc 或关闭均不改原日期时间、不触发提交，并把键盘焦点恢复到发起控件。身份切换或会话失效关闭旧面板并清理暂存值，不把焦点抢回旧账户表单。
- 提醒标题输入框与日期时间触发控件采用协调的同高尺寸并顶对齐；标签、长翻译及不同浏览器的原生输入外观不能造成一高一低或时间文字被裁切。验收可见输入控件和键盘焦点的真实位置，不以外层容器碰巧等高代替。
- 今日新建且尚无保存记录的日志标头显示完整本地日期、星期及 `HH:mm:ss`，明确标为当前编辑时刻；工程默认在首次建立该账户／日期草稿时记录此时刻，普通重绘不把它改成新的记录时间。已有日志使用服务端真实字段显示“最近保存”等对应含义，当前字段有 `updatedAt` 时据其展示，不推测缺失的创建时刻。历史空日只显示所选日期及星期，不把历史日期与当前时间拼成历史记录；日期聚合、所选账户归属与原有私密权限保持原合同。

### 1.8、<span id="navigation-sound">Web 左侧导航的啄木鸟敲木音效</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

用户要求本轮 Web 左侧导航在鼠标悬停时提供近似啄木鸟敲木的短促音效。工程实现采用 Web Audio 程序合成短木质敲击（约3—5次短连敲），不引入外部音频资源；这是合成音效，不写成真人／现场录音或已经完成听感验收。

- 服从浏览器播放限制，首次有效鼠标／触控按下或键盘用户手势解锁后才允许悬停播放，不能承诺用户从未操作时就会发声；音效不得抢焦点、拦截点击或改变导航结果。
- 提供可关闭开关并保留本机偏好；相邻导航快速掠过须节流且不叠响，页面隐藏／离开时停止播放并清理本轮音频。初始化、恢复或播放失败时保持导航可用，不更改设备音量及系统设置。

### 2.4、<span id="work-log-design">个人日志的接口与数据评审</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

当前身份基础仍是既有合成演示账户，已知演示密码与一键角色登录只用于合成测试；账户级读写隔离验收不替代正式员工身份验收。真实私密日志使用前须落实独立员工账户与凭据管理，不能把演示角色按钮当作个人身份认证。

本节为本轮 Web 与后端协调后的实施合同，属于工程设计，不代表功能已经实现或测试通过；先保存本需求文档，再进入业务代码实施。实际字段、错误码及限制须随代码同步到[后端接口合同](../../代码/后端/README.md#api-contract)。所有路径以前缀 `/api/v38` 为基准，采用现有 Bearer 会话、稳定请求键与版本校验。普通账号仅本人可写，管理员可显式选择其他有效账户只读；日志不混入通用工单 bootstrap、工单导出或公共页面。提醒独立归当前账户，管理员查看他人日志也不能查询其独立提醒。

“全部日志”跨月份查询、点击详情及本人按版本删除属于本轮已确认的补充范围，沿用上述私密权限；查询须能分页或加载更多，删除须明确确认并同步正文与所属媒体的访问状态。具体列表及删除合同如下，不由页面自行猜测或借已有按月结果代替。

| 接口 | 约定请求／响应与权限 |
| --- | --- |
| `GET /work-logs?month=YYYY-MM&ownerId=&timeZone=` | `ownerId` 可省略表示本人，`timeZone` 为 IANA 标识；返回 `{ownerId,month,today,timeZone,readOnly,items}`，条目含日期、正文、媒体元数据、版本及修改时间。仅管理员可有他人选择用的 `owners[{id,name,role}]`；普通账号不能由列表获知其他账户日志摘要 |
| `GET /work-logs?scope=all&page=1&pageSize=20&ownerId=&timeZone=` | 跨月份按日期降序返回当前所选账户的授权记录，保留原归属／时区／只读元数据并返回 `scope,page,pageSize,total,hasMore,items`；默认每页20条，可选1—100条，删除墓碑不计入列表，分页或加载更多不能混入其他账户 |
| `GET /work-logs/{date}?ownerId=&timeZone=` | `date` 为合法 `YYYY-MM-DD`；返回所选有权日志，无记录时版本为0的空日志。默认打开今日不限制本人编辑历史或未来日期；`readOnly` 由是否查看他人决定，不由日期决定 |
| `PUT /work-logs/{date}` | `{text,mediaIds,version,timeZone}`，归属取当前会话，保存本人所选日期并返回完整日志；新建版本0，已存日志校验当前版本，不接受替他人写入 |
| `DELETE /work-logs/{date}` | `{version,timeZone}`，仅本人明确确认后按当前版本删除；成功返回 `{ok,ownerId,date,version,deleted:true}`。内部墓碑保留版本防止旧写入覆盖删除后重建，原媒体访问失效；管理员查看他人仍只读 |
| `POST /work-logs/{date}/media` | `{name,mime,dataBase64,version,timeZone}`，仅本人所选日志；验证后原子追加媒体并增加日志版本，返回日志。该上传为独立提交，附件成功不冒充尚未提交的文字已保存 |
| `GET /work-log-media/{id}` | 鉴权返回媒体元数据与 `dataBase64`，仅本人或管理员只读查看；每次检查日志归属，不开放静态媒体 URL，不借工单授权放行个人附件 |
| `GET /reminders`、`POST /reminders` | 仅当前账户的待办提醒；记录含 `id,ownerId,title,body,dueAt,timeZone,status,version,createdAt,updatedAt`，可有 `notifiedAt`；标题1—200字符、正文0—2000字符为工程限额。`dueAt` 为 UTC RFC3339，`status` 为 `pending/notified/done`，创建成功直接返回记录 |
| `PUT /reminders/{id}`、`DELETE /reminders/{id}` | 仅本人按版本修改、完成或取消／删除；改提醒时间重新进入 pending 并形成新版本，取消／删除后不得触发旧提醒。更新成功返回记录，删除成功返回 `{ok:true,id,ownerId}` |
| `POST /reminders/{id}/fire` | `{version}`，由后端原子核验当前账户、版本、到期及未完成状态后认领触发，返回 `{claimed,reminder}`。只有本版本成功认领方展示 tips；多标签页、刷新与重开不各自重复触发，不把已触发当成待办已完成 |

最小数据职责为 `WorkLog(ownerId,date,version,text,media,updatedAt,deleted)`、私有媒体归属及内容、独立 `Reminder`。当前日志没有可据以展示的 `createdAt`；删除后保留 `deleted` 墓碑和递增版本，清空正文与所属媒体，旧请求响应不重新暴露已删除内容。日志按账户＋日期唯一；媒体保存稳定 ID、归属、名称、MIME、字节数及内容，日志响应只带 `{id,name,mime,size}`；提醒归属由会话确定，持久化事件及触发版本不能仅靠页面定时器维持。新增集合纳入现有加密聚合快照，旧快照缺少集合按空集合兼容，不重置既有工单、权限及数据；备份／恢复覆盖新内容并继续校验最新账号授权。读取／下载、管理员查看和写入失败的审计不记录正文、媒体内容或凭据。

本轮媒体采用可配置工程限额：图片支持 PNG／JPEG／GIF／WebP，视频支持 MP4／WebM／QuickTime；不接受 SVG／HTML。`WB_JOURNAL_MEDIA_MAX_BYTES` 控制单文件字节数，默认视频16 MiB、配置硬上限32 MiB；图片同时受8 MiB固定上限约束，与配置取较小值。每日日志最多8个附件、媒体合计32 MiB，正文最多20000字符。以上是小规模加密快照的实施默认，未作生产容量保证；上传还需核验实际格式／内容，明确 base64 膨胀及 HTTP 请求体上限，不为视频放宽无关工单 API。剪贴板文件与本地文件使用同一校验、预览和鉴权路径，具体兼容及保留策略见 Q-007。

沿用既有错误和原子性合同：未登录／失效会话拒绝，跨账户读写与附件请求拒绝且不泄漏内容；版本冲突／同键异内容不覆盖；正文／媒体／时间非法不保存；持久化失败不交换内存状态或留下半份操作。日志文字按纯文本安全渲染，媒体 Blob 与草稿随身份变化释放。提醒认领成功表示服务器已登记本次展示尝试，不保证页面崩溃／关窗前用户实际看到；未来若要求可靠送达或已读回执需独立评审，不据单次 fire 宣称具备正式消息推送能力。

### 2.5、<span id="inventory-purchase-design">库存明细与采购附件接口</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

本节延续[库存与采购需求](#inventory-purchase-detail)，路径均以 `/api/v38` 为前缀；不改变原有借还数量、采购收货和角色权限。创建／追加使用现有 Bearer 会话与稳定 `Idempotency-Key`，已有采购变更另校验当前版本，读取原件逐次复核当前账户授权。

| 接口 | 请求／响应与授权 |
| --- | --- |
| `GET /parts/{id}` | 仅内部角色；返回 `{part,loans,purchases}`，库存字段为 `id,name,sku,available,quarantine`。借还仅管理员／仓库／调度可看全部，工程师只看本人借还；关联采购沿下述采购读取权限过滤，不能由库存入口扩大授权 |
| `POST /purchases` | 既有 `{supplier,partId,quantity,unitCents,note}` 可加 `attachments:[{name,mime,dataBase64}]`，管理员／仓库／调度登记；采购与首批附件同事务保存，成功返回不含原件的采购详情 |
| `GET /purchases/{id}` | 返回当前有权采购与 `files` 元数据；管理员／仓库／财务／调度可读，供应商仅可读 `supplier` 与当前账户 ID 或名称匹配的采购；无权或不存在均不返回资料 |
| `POST /purchases/{id}/attachments` | `{version,name,mime,dataBase64}`，仅管理员／仓库／调度按当前采购版本追加；成功增加采购版本并返回最新详情，版本冲突／超限／持久化失败不留下半套附件 |
| `GET /purchases/{id}/attachments/{fileId}` | 采购与附件双重归属校验后返回原件二进制；继承采购读取权限，先保存必要读取审计，响应 `Cache-Control: no-store` 并强制附件下载。网页仅把已鉴权图片转为本会话 Blob 预览，其他文件下载，不开放静态 URL |

`Purchase.files` 元数据为 `{id,name,mime,size,uploaderId,createdAt}`；创建、收货、详情、首屏与幂等重试均剥离 `dataBase64`，原件仅保存在加密快照并由上述下载接口返回。支持 PNG／JPEG／GIF／WebP、PDF、TXT／CSV 与 DOCX／XLSX／PPTX；按声明 MIME 和实际内容共同验证，拒绝 HTML／SVG、可执行文件及伪装格式。单文件非空且最多8 MiB，每单最多8件、原件合计32 MiB；上传 JSON 沿用12 MiB请求体上限，Base64 膨胀计入请求体，单次请求不能以总额32 MiB代替请求体限制。名称最多180字符，拒绝路径分隔符、引号及控制字符，不据文件名读取服务器本机路径。

网页采购表单可从本地选取或主动粘贴一个文件，登记时可随单提交，后续从明细追加。失败及结果未知时保留原输入与请求意图，不把真实文件复制到独立合成演示；切换身份、关闭或替换明细后迟到回包不能重开旧弹窗或生成旧原件预览。附件不改变库存数量、采购收货与工单证据授权；当前没有采购附件删除接口，不能把日志删除语义套到采购文件。
