## 🔥 <span id="前言">前言</span>

配对反部署从首次部署保存的原点清单核验归属。已登记的后端、隧道与菜单按PID、启动时间及完整命令匹配后停止；本项目新增的程序、SDK、依赖和构建缓存撤回，原有程序／专属环境恢复原件。复用的共享SDK与其它项目始终保留。

在上一级系统目录双击 [双击反部署（快捷入口）.desktop](../双击反部署（快捷入口）.desktop)，只转交本目录内唯一的配对反部署实现，复用原有自述、原点核验、数据备份默认／清零选择和危险确认。另一个 [双击部署（快捷入口）.desktop](../双击部署（快捷入口）.desktop) 用于部署；按名称选择，两个入口不互相替代。桌面快捷文件需要图形会话、终端模拟器及文件管理器允许启动，无桌面时使用下方 Bash 命令。

## 一、<span id="paired-undeployment">配对反部署入口</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

在本目录打开终端执行：

```shell
/bin/bash './【Linux】反部署维修工作台.sh/【Linux】反部署维修工作台.sh'
/bin/bash './【Linux】反部署维修工作台.sh/【Linux】反部署维修工作台.sh' --plan
/bin/bash './【Linux】反部署维修工作台.sh/【Linux】反部署维修工作台.sh' --check
```

- 普通入口先阅读自述并按回车；fzf默认选择“数据库／文件数据备份”，也可选择“清零”或取消。第二层执行确认默认取消；清零还须按空格后回车。Esc、空选和选择器异常不进入删除。
- 反部署复用已有fzf，按 `WB_FZF_BIN`、PATH、本项目专属工具及既有共享缓存发现；不会为了删除再安装SDK。缺少选择器时停止并说明如何指定现有工具。
- `--check`／`--plan` 不下载、不创建缓存或日志、不停止进程、不读写数据库；没有原点清单时明确显示保留旧环境。

默认备份模式把当前文件数据、附件／签名聚合快照、匹配密钥和私有部署配置复制到 Runtime 外的独立操作目录，逐项核验内容后才清理当前应用数据。文件快照存在时，还须用原程序的 `-backup` 成功解密并生成有效加密聚合备份与SHA256清单；缺少原程序、密钥不匹配或校验失败均拒绝清理。备份目录与密钥应按敏感业务资料保管。

媒体原件随聚合备份保存为 `database.wbbak.media/` 旁件目录，须与主文件、`.manifest.json`、匹配密钥一并保管。脚本只核对清单顶层 `sha256`，不会混入 `media[*].sha256`。每次聚合备份尝试使用独立 `database-attempt.*` 目录，失败候选、旧备份与未知旁件均保留；成功引用记在操作目录的 `database-backup.path`，续跑清零仅使用经路径归属核对的引用，旧版已验证固定文件仍兼容。

TiDB 使用原程序的 `-backup` 生成加密应用聚合备份及摘要清单，校验SHA256并配对保存原密钥；成功后通过 `-clear-storage -confirm-clear-storage` 清零本应用 `v38_workbench_snapshot` 的 `id=1`。备份模式同时传入 `-clear-storage-backup` 绑定已验证备份；备份后出现新业务内容时拒绝清零，保留新数据。清零使用事务行锁、解密与版本条件；不删除数据库、表结构、权限、其它行或其它服务。应用聚合备份不能代替数据库完整灾备。数据库连接、备份、摘要或清零失败时停止后续移除。

“清零”模式不创建当前业务数据备份，明确确认后清理同一应用范围。两种模式均保留部署前原程序／专属依赖恢复副本；备份模式先归档当前业务数据，清零模式按明确选择舍弃当前业务数据。不能把清零当成恢复旧业务数据或自动重置外部数据库服务。

首次原点清单保存在项目独立 Runtime 的 `deploy-state/`，记录原程序／专属环境副本、当前指纹、数据与密钥位置、进程身份及私有数据库连接配置；权限只面向当前用户，不写入普通日志。重复部署复用首轮原点，配置变化时拒绝覆盖旧清单。部署与反部署通过同一个操作锁串行化。

缺失清单的旧部署、PID复用、权限不明、运行中的写入者、软链接、超出项目范围的目标、原件备份损坏、部署后人工修改、未封存会话摘要或未知新增内容均会保留现场并停止。旧部署没有记录安装前状态时，脚本不会推测哪些共享SDK可以删除；应先核对旧资料与环境归属。当前操作锁残留时先核对原运行终端及状态，不删除锁强行绕过。

备份／审计根默认是本项目 Runtime 同级的 `UndeploymentBackups/`，每次使用独立 `repair-undeploy.*` 目录。备份根与显式外置数据、密钥也必须互不包含，防止复制进待删范围或递归自复制。可通过 `WB_UNDEPLOY_BACKUP_DIR` 指定位于Runtime、专属环境和项目源码之外的绝对路径。`WB_RUNTIME_DIR`／`WB_ENV_ROOT` 必须与原部署一致；日志在独立操作目录的 `operation.log`。失败保留状态、原件及已完成备份，不输出恢复成功。部署前不存在的父目录有独立清单，只尝试回收这些当前为空的目录；原有空目录、用户后来新增内容及已生成的外置备份／审计目录保留。数据阶段、外置操作目录与逐项原件恢复均有检查点；已核验恢复原点的对象续跑时跳过，中途恢复失败可在相同数据选择下重试，不重复备份已处理的数据或重新清零。

## 二、<span id="stop-service">当前停止方式</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

当前双模式入口管理本次前台子进程，Ctrl+C统一停止本次后端与Quick；未注册系统服务，因此没有可直接套用的服务卸载命令。另行常驻的资源必须先逐项确认，只停止本项目。

## 三、<span id="retain">数据备份与保留</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

普通Ctrl+C停止仍保留业务数据、密钥及配置。完整反部署按上方fzf选择先备份归档或明确清零；不可通过删除整个Runtime或共享环境代替归属核验。

现有[配对反部署入口](./【Linux】反部署维修工作台.sh/README.md)提供原点恢复、数据备份默认／清零选择及冲突保护。返回 [本系统部署文档](../README.md) 或 [部署入口](../Deployment/README.md)。

## 四、<span id="local-tunnel">本地部署＋内网穿透的停止与撤回</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

本节适用于按[本系统教程](../README.md#local-tunnel)启动的双模式入口，或另行人工启用的Go＋cpolar。双模式入口在其终端按Ctrl+C会停止本次后端和本次隧道，异常退出也只清理本次PID；完整移除与原点恢复使用[配对反部署脚本](./【Linux】反部署维修工作台.sh/README.md)。

1、使用双模式入口时先在该终端按 `Ctrl+C`，随后检查本地与外部新请求均已失败；以下独立客户端步骤只用于另行手工运行的隧道。先停止公网入口。cpolar前台窗口按 `Ctrl+C`，Cloudflare Quick窗口同样按 `Ctrl+C`；服务模式到本人实际客户端管理界面停用repair隧道，不按模糊进程名批量结束程序。一个cpolar进程同时托管repair和academic时，退出会使两个项目都断开；只停维修可在GUI只停repair，或明确接受另一站短暂重连后仅运行academic。

2、控制台核对维修域名不再指向在线隧道。停止连接并不自动解除固定子域名预留、删除命名Tunnel或取消付费续订；不再使用时按所选产品在本人控制台解除相应映射／预留。自有域名DNS另外撤回，保留学术项目和其它服务使用的记录；共享Tunnel只移除维修主机名，不删除整个共享Tunnel。

3、让外部手机关闭Wi-Fi，以新请求访问原维修公网 `/api/v38/healthz` 和受保护API确认失败。已经打开的页面可能仍展示缓存或本地演示回退，页面没消失不能证明连接仍在。

4、在维修Go前台窗口按 `Ctrl+C`，确认本机8098不再监听；学术8080仍需使用时保持其进程和数据不变。本机检查命令：

```shell
ss -ltnp | rg ":8098"
```

未检出监听才符合停止预期；命令退出或没有显示进程信息不授权关闭其它服务。Linux没有rg时可用本机已有工具检查ss输出，不能为停止步骤强行安装开发工具。

5、若曾自行注册常驻项，另行记录并停用对应MacOS launchd、Windows服务／任务计划或Linux systemd单元，确认重启后不会自动重新公开；本任务没有安装这些单元，不照抄未知服务名执行卸载。若临时改了电源设置，按原记录恢复，不重置其它系统设置。

6、默认保留维修加密数据、匹配密钥、附件、有效配置及备份。先停止写入再备份或迁移，不在Mac／Windows两台设备上同时启动同一文件快照写入。停止／撤回公网不会擦除cpolar本机令牌；凭据泄露时在对应服务控制台撤销并重新授权，令牌不写入仓库或排查截图。

以上是停止和撤回指引，未实际停用公网隧道、取消订阅、删除DNS或执行系统服务操作；逐项完成后才记录本机与外网复查结果。
