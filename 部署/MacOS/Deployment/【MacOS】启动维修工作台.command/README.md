**部署快捷入口：** 可在本系统目录直接双击 [【MacOS】双击部署（快捷入口）.command](../../【MacOS】双击部署（快捷入口）.command)；它调用本目录下的规范部署实现，复用同一自述、确认与参数，不另存部署逻辑。

## <span id="jobs-toc-heading-1" data-jobs-toc="v2">🔥 <font id=前言>前言</font></span><!-- jobs-toc:heading-end -->

`./【MacOS】启动维修工作台.command` 通过fzf选择两种部署模式，负责构建 [**Go**](https://go.dev/) 新工作台并在本机回环地址运行。本系统目录提供 `【MacOS】双击部署（快捷入口）.command`，直接双击即可进入同一部署流程。

**扫码入口：** 启动后保留各端完整 URL，分别显示前端用户／工程师工作台 `/` 与后台管理网页 `/admin/` 的两张离线二维码。宽度足够且支持颜色时直接在终端扫码；否则用“打开网页”菜单中的“打开扫码页面”打开本次 HTML，页面内嵌 SVG，并保留 PNG／SVG 文件。回环码明确“仅本机，手机不可用”，公网码使用本轮实际隧道 URL，扫码后继续执行现有业务登录和权限校验，无隧道邮箱验证。二维码工具复用已有 Go 和锁定依赖，失败只告警并保留 URL／服务；产物位于本次 Runtime 会话。隧道地址变化会使旧页面失效并生成新码，退出也标记失效；已另存的图片不能撤销，重新部署必须使用新码。来源及参数见[二维码工具](../../../公共组件/地址二维码/README.md)。

## 一、<span id="script-use">运行方式与行为</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

双击脚本，先阅读内置自述并按回车，再用 [**fzf**](https://github.com/junegunn/fzf) 的 `↑`／`↓` 选择模式，回车确认，`Esc` 取消。本地模式只需再按回车确认公开本次临时 HTTPS 入口；不收邮箱，不要求输入 `PUBLIC`，取消时保留旧实例。确认后先核验并停止本项目旧部署，等待其退出封存、解锁，再准备依赖与构建，检查本次后端健康后才建立隧道；服务器模式只运行后端。启动成功后自动显示“打开网页”菜单，选择本次公网地址或[本机工作台](http://127.0.0.1:8098/)并回车，交给系统默认浏览器打开，打开后可反复选择；服务器模式列本机地址及扫码页面，回环码明确仅本机。

网页菜单按 `Esc` 或选择“收起菜单”只收起菜单，服务继续运行；在原终端按回车再次显示菜单。`Ctrl+C` 或关窗停止本次菜单、后端和隧道，保留数据、密钥、配置与首轮原点。独立会话守护监测入口或终端父进程异常结束，核验身份后完成本轮回收、二维码失效与解锁，再次双击可部署。浏览器打开失败时提示后仍可重选；系统接受打开请求不代表公网访问已验收。菜单等待期间持续监控本次服务，后端或隧道退出会结束菜单并执行本次清理。

| 部署方式 | 访问者需要做什么 | 适用场景 |
| --- | --- | --- |
| 本地部署＋内网穿透 | 部署者按回车确认公开；访问者直接打开本轮 HTTPS 链接，继续按现有业务流程登录 | 浏览器公开演示或原生 App／API 联调，仅用合成数据 |
| 服务器部署 | 默认只提供本机入口；正式域名、TLS 与访问控制另行配置和验收 | 只运行后端，不自动建立隧道 |

**MacOS 本地模式统一使用公开演示入口。**任何取得链接的人都能到达服务入口，仅使用合成资料；随机网址与固定演示身份不能充当私人认证，不接入真实客户数据。本次简化只适用于 MacOS，其他平台的邮箱／`PUBLIC` 流程保持各自说明。自述、模式选择、本地公开确认取消及只读检查不接管旧实例；确认重启后若后续失败，停止新流程，不承诺恢复旧进程。未知归属、PID 身份变化或反部署作业保留并报告，不删除锁强行绕过。

终端运行：

```zsh
/bin/zsh './【MacOS】启动维修工作台.command'
```

入口按自身真实位置定位项目，支持中文、空格及目录迁移。脚本位于部署目录独立包内，解析软链接后逐级定位含Go源码的项目根。确认前只展示说明；确认后按模式准备机器环境工具，构建成功才替换本项目 Runtime 内的 `workbench`，本次health通过后才允许穿透。

模式选择前的 `prepare_fzf` 只读复用健康选择器；缺失时按锁清单校验并下载到本次会话的 `RUN_DIR/bootstrap-environment`，不改动旧部署的项目专属工具缓存。该目录随本次会话登记原点与资源清单，取消可保留本次记录，旧实例继续运行。

## 二、<span id="script-dependencies">依赖与配置</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| 配置 | 行为 |
| --- | --- |
| `GO_BIN` | 显式指定已有Go，版本落后官方目标或配置损坏时停止；相对路径按项目根解析 |
| `PATH` | 未设GO_BIN时，按当次官方目标检查现有Go |
| 机器公共环境 `Go/go版本/MacOS-架构/go/bin/go` | 与PATH及本项目缓存一起按实际版本择新，健康且不低于官方目标才复用 |
| `GOPROXY`、Go 用户配置 | 显式配置（包括空值、`off`）原样保留；未配置且使用官方默认时，仅本次构建使用 `https://goproxy.cn\|https://proxy.golang.org\|direct`，网络错误自动回退 |
| `../../../../代码/后端/后端代码` | 当前 Go 源码与 `cmd/workbench` 构建入口 |
| `WB_ADDR` | 默认 `127.0.0.1:8098`，仅允许回环主机与有效端口 |
| `WB_DATA_DIR`、`WB_WEB_DIR` | 默认本项目 Runtime 内的 `data`、项目内 `代码/前端/PC端/Web/维修工作台`；相对配置按项目根目录解析 |
| `WB_KEY_FILE` | 交由后端；相对路径按项目根目录解析，不要将密钥放入公开日志 |
| `WB_TIDB_DSN`、`WB_REQUIRE_DB_TLS` | 交由后端；指定数据库会初始化快照表，不要使用生产目标或公开 DSN |
| `WB_BACKUP_DIR`、`WB_BACKUP_INTERVAL_MINUTES` | 相对备份路径按项目根目录解析；未配置目标时不启用独立定时备份，间隔默认 1440 分钟 |
| `WB_DEPENDENCY_CHECK_TIMEOUT_SECONDS` | 每模块更新检查超时，默认30秒，可设置1—300秒；超时不自动升级业务库 |
| `NO_COLOR` | 改用纯文本展示 |

脚本每次正常部署检查官方稳定工具；旧版不因健康而跳过。新版本进入项目专属机器缓存，不覆盖系统或显式路径，不安装全局工具／服务，不执行容器部署。后端会初始化明确配置的演示存储并写入业务／备份，仅应使用专用目标。完整跨平台运行与数据说明见 [项目 README](../../../../README.md) 和 [部署文档](../../../README.md)；系统入口见 [MacOS 部署资料](../../README.md)。

构建依赖链为引导Go → 官方稳定版本解析器 → 版本与功能达标的最终Go → 业务依赖更新报告 → 本轮模块锁副本与校验 → 新二进制 → 本机健康检查 → 所选隧道。未自定义下载源时，优先使用 [Goproxy.cn](https://goproxy.cn/)；其不可用时转向官方模块镜像，再直接获取源码。[Go 官方模块协议](https://go.dev/ref/mod#goproxy-protocol)规定 `|` 会在超时等错误后回退，默认配置的逗号只在 404／410 后回退。启动器不会执行 `go env -w`，不修改系统代理、Shell 配置、`GOSUMDB` 或私库策略；本次构建结束即撤回下载源设置。仍按 `go.sum` 校验，`-mod=readonly` 防止构建改写依赖清单。

### 2.1、<span id="minimum-machine">最低支持的机器配置</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

本入口每次从源码构建，最低资源预算为 2 个可分配逻辑核、项目可用内存 4 GiB、20 GiB 可用 SSD；MacOS 整机至少 8 GiB RAM，且扣除系统、浏览器等占用后仍须满足 4 GiB。随附 Go 1.27.2 按 MacOS 13 或以上、Apple Silicon 64 位准备；Intel Mac由入口按需准备匹配工具并构建，仍须单独验收。工具链系统门槛依据 [Go 官方最低要求](https://go.dev/wiki/MinimumRequirements)。

仅直接运行已有二进制＋文件存储时可按 2 核、项目可用内存 2 GiB、10 GiB 可用 SSD 准备，不能把此档用于本脚本。同机运行 TiDB unistore 演示按 4 核、16 GiB 整机 RAM（项目可用 8 GiB）、40 GiB 可用 SSD 准备；容器软件、虚拟化与系统要求另行满足。默认 API 仅回环 8098，无公网带宽下限；首次构建获取依赖需联网，无需独立显卡。

这些数值是少量合成数据的工程预算，未做最低资源或并发压测，正式生产尚无已验收最低值；磁盘另留数据、备份与恢复副本空间。完整条件见[总部署文档的最低配置](../../../README.md#minimum-machine)。

## 三、<span id="script-logs">日志、风险与验证</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

主日志位于系统临时目录中的 `维修部署-进程号.log`，确认后初始化，构建输出同步显示在终端并写入日志，后端输出也写入其中；隧道日志在本项目 Runtime 内本次 `deploy-session.*` 中，实际位置由终端提示。默认保留既有业务数据。只有本项目的新工作台进程由此入口启动；停止不会删除数据。

出现 `proxy.golang.org ... i/o timeout` 表示依赖下载失败，尚未完成源码构建。默认下载源已包含网络错误回退；若终端显示“沿用显式／用户配置 GOPROXY”，先核对自己指定的源和网络策略。完整错误直接显示在终端，失败保留原退出码，不替换或启动旧二进制；不通过关闭校验解决网络故障。

本机健康检查请求 `/api/v38/healthz`；裸路径 `/healthz` 不属于当前工作台接口。手工检查时使用相同 API 路径，首页能打开不能代替健康检查。

默认账号与明文回环连接供合成数据演示。真实资料须先落实可信加密连接、最小授权、独立密钥保管与独立备份恢复；默认同盘数据与密钥不能抵御整机损失。

静态检查：

```zsh
/bin/zsh -n './【MacOS】启动维修工作台.command'
```

隔离回归入口见[构建验证说明](../../../../测试/部署/MacOS/【MacOS】验证工作台构建.command/README.md)，覆盖下载源配置保留、构建失败、旧产物保护和进程回收。MacOS ARM64 已通过真实依赖下载与编译，并在独立合成数据目录完成服务器模式的健康、工作台及管理端访问；公网临时隧道未据此验收。业务验证范围见 [实现范围](../../../../需求/技术方案与实现范围/技术方案与实现范围.md#verified)。本项目旧实例按身份完成退出后仍有其他服务占用端口时，更换回环端口，不停止该服务。

停止本入口自己运行的前台服务使用 `Ctrl+C`，保留业务数据；完整反部署按原点清单恢复环境并通过fzf选择备份默认／清零，详见 [停止与反部署说明](../../Undeployment/README.md)。

新增客户端启动后访问 `/admin/`（Web管理）、`/admin-flutter/`（Flutter管理）、`/client-flutter/`（Flutter用户）；Flutter入口需先按各端README构建。`WB_ADMIN_DIR`、`WB_ADMIN_FLUTTER_DIR`、`WB_CLIENT_FLUTTER_DIR`、`WB_ADMIN_CONTRACT_DIR` 的相对值和默认值均按项目根解析，和当前启动目录无关。

## 四、<span id="local-tunnel">本地部署＋内网穿透</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

部署入口提供可交互的双模式选择。正常运行先展示影响范围，回车授权本次项目内准备，再必须通过[**fzf**](https://github.com/junegunn/fzf)选择“本地部署＋内网穿透”或“服务器部署”；不是先装好一套云服务再开始。

在终端进入本文所在目录后执行下面的本系统入口；脚本从自身位置定位项目，支持中文／空格及项目迁移，不依赖调用时的工作目录。可从本系统目录双击 `【MacOS】双击部署（快捷入口）.command`，或在终端使用 zsh 运行包内脚本。

```zsh
/bin/zsh './【MacOS】启动维修工作台.command'
```

- 选择“本地部署＋内网穿透”：模式确认后查询Go／fzf／本地模式cloudflared的官方最新稳定版；已有工具仅在实际版本不低于目标且功能健康时复用，否则按官方摘要校验下载到项目专属机器缓存，不覆盖系统或显式路径文件。构建成功且本次子进程通过本机health后才连接免费Cloudflare Quick Tunnel，无需注册账号、购买域名或云主机。Quick只为本次子进程使用会话内空配置{}并清除继承的TUNNEL_*，不会改动本人已有cloudflared配置或父进程环境。首次下载和Go依赖需要网络；临时网络故障持续退避重试，Ctrl+C可取消；来源、摘要或参数错误明确停止，不跳过校验。系统还需自带基础下载／解压／校验工具（Shell需要curl、tar与shasum或sha256sum）；不会自动执行sudo、brew、apt、dnf或全局安装。来源清单见[锁定文件](../../../deploy-tools.lock.tsv)。

- 本地模式直接采用公开演示／App 联调：选择模式后说明公开范围，按回车继续，其他输入或输入结束取消；不再选择“外网访问方式”、填写邮箱或输入 `PUBLIC`，也不使用继承的 `WB_TUNNEL_ALLOWED_MAIL` 加回邮箱门禁。取得链接的人都能到达服务入口，业务登录和权限继续按现有实现执行；仅使用合成资料，固定演示身份与随机网址不能充当私人认证，不接入真实客户数据。

- 选择“服务器部署”：仅准备Go／fzf、构建并前台运行，保留 `127.0.0.1:8098` 和原有数据／密钥语义，不建立隧道，不购买机器，不自动配置反向代理、TLS、服务注册或防火墙。需要固定cpolar地址时先用该模式运行本机服务，再按本文可选cpolar步骤配置，避免同时建立两套公网入口。

- fzf 使用 `↑`／`↓` 与回车选择，`Esc`／空选取消；自述、模式选择及本地公开确认取消均保留旧实例，不构建或启动新业务，已经校验好的 fzf 缓存和本次诊断日志可保留。确认重启后才按登记身份接管本项目旧实例；后续失败不承诺自动恢复旧实例。初始说明前没有业务写入；Go 路径可用 `GO_BIN` 指定，fzf／cloudflared 可用 `WB_FZF_BIN`／`WB_CLOUDFLARED_BIN` 指向本人已核验工具，不需要修改全局 PATH。默认文件模式须确保未误设 `WB_TIDB_DSN`；既有数据库用户保留自己的已核验配置，不把切换为空值当作数据迁移。

只读审阅（不会下载、写缓存／配置／日志、构建、启动后端或连接公网）：

```zsh
/bin/zsh './【MacOS】启动维修工作台.command' --check
/bin/zsh './【MacOS】启动维修工作台.command' --plan --mode local
```

`--check`／`--plan`（PowerShell为 `-Check`／`-Plan`）是结构和计划检查，不能代替实机部署验收；模式参数只供计划审阅，正常入口不能用它跳过fzf。

- 取得本次公网地址后自动显示“打开网页”fzf菜单；选择公网或本机地址并回车，即交给默认浏览器打开，随后回到菜单继续选择。终端和服务保持运行；Esc或“收起菜单”仅收起菜单，回到原终端按回车可重新显示。服务器模式列本机地址及扫码页面，回环码明确仅本机。Quick Tunnel每个项目获得自己的随机HTTPS地址；维修8098与学术8080分别用各自部署入口启动，不共用一个服务端口。URL仅表示取得入口，必须完成本节外网验收。Quick官方没有可用性保证，最多200个在途请求且不支持SSE；中国大陆不同运营商可达性另行实测。固定地址可选择下方cpolar或自有域名命名Tunnel，不能把Quick地址写成长期生产入口。[Quick限制](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

- `Ctrl+C`、关窗及任一子进程异常时回收本次后端和隧道，保留数据。独立守护处理入口或终端父进程异常退出；再次部署只接管身份可核验的本项目旧实例，其他服务占用端口时停止并报告。不会使用 `killall` 或按名字、端口批量结束进程。隧道取得地址默认限45秒，可在本次进程设置 `WB_TUNNEL_START_TIMEOUT=90`（1..600）；应用构建耗时不计入此地址等待。日志位置在终端显示：主日志位于系统临时目录，本次后端日志写入其中，隧道日志位于本项目独立 Runtime 下的 `deploy-session.*`。日志可能含公网地址，分享前脱敏，不把令牌或数据密钥写进 README 或提交仓库。

两项目均可默认文件存储，维修使用独立数据和密钥，学术使用自己的文件目录；网页、API和文件下载各自整站同源，保留公网Host，不加Host rewrite，不把API填成手机自己的127.0.0.1。两个项目的API失败会回退本地演示，必须在移动网络验证公网health、登录、新建合成记录→刷新重读、附件上传／权限拒绝，页面打开或假数据能操作不能算成功。

需要国内固定地址时可选[**cpolar**](https://www.cpolar.com/pricing)：当前公开免费档1Mbps／随机地址，基础99元年2Mbps／3个保留子域名，专业149元年3Mbps且支持自有域名；实际资格和价格以官网为准。一个客户端进程可显式启动repair和academic两条HTTP隧道，先读[详细平台教程](../../README.md#local-tunnel)中的完整YAML、固定子域名／地区和Host要求，再执行；不使用启动全部SSH／远程桌面样例的命令，已有GUI／服务不再重复开一个客户端。

电脑睡眠、合盖、重启或断网会中断访问；可由使用者选择保持接电唤醒，不执行全局电源策略。停止后用全新公网health／API请求确认撤回，旧页面仍可能显示缓存／本地演示；固定域名预留、DNS、订阅和自行注册的后台常驻项另行撤销，保留数据／密钥／附件／备份。平台工具、完整可选双隧道命令、外网验收和故障排查见[本系统详细教程](../../README.md#local-tunnel)。

真实依赖安装、公网连接和本系统业务穿透需在目标环境完成验收。

本机＋内网穿透属于临时运行：确认公网访问前和公网地址就绪后，运行日志都会醒目显示“关闭此运行终端，服务将结束”。支持颜色的终端使用红色加粗；`NO_COLOR`、`TERM=dumb` 或非交互输出使用纯文本，落盘日志不含颜色控制码。按 `Ctrl+C` 正常停止，业务数据和匹配密钥保留。



首次部署在 Runtime 的 `deploy-state/` 保存原程序及项目专属环境原件、指纹与进程身份；重复部署不覆盖首轮原点。已有共享工具仅在版本与功能达标时复用，新工具、下载与Go缓存写入机器环境 `Projects/RepairWorkbench/<项目标识>/` 下的 `Tools/`、`Downloads/`、`GoCache/`，以便按归属完整撤回。配套[反部署入口](../../Undeployment/README.md)恢复原件并处理数据；未记录原点的旧部署不会推测删除共享SDK。

**终端配色保护：** 独立运行时，在支持完整保存与恢复配色的交互终端中临时使用黑底白字及统一强调色；正常结束、失败或可捕获中断后恢复进入前的配色，不修改终端全局偏好或 Shell 启动配置。不支持完整保护、无交互终端、`NO_COLOR`、既有纯文本模式和 Sourcetree 场景不切换配色，并沿用纯文本输出约定。强制终止（如 `kill -9`）无法由脚本自身保证恢复，请使用运行时显示的独立恢复入口。
